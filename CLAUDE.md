# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

macOS-only pipeline that pulls PLAUD recorder audio from PLAUD cloud (free tier, official `@plaud-ai/cli` only), transcribes it through a 3-tier engine chain (AssemblyAI cloud diarization → local WhisperX diarization → local whisper.cpp — the first two are opt-in, whisper.cpp is the always-available default), optionally summarizes via the Claude API (`claude_summarize.py`, urllib, model `claude-opus-5`) into a six-section meeting note with speaker-name inference, optionally cross-verifies the summary against the transcript via the OpenAI API (`gpt_verify.py` — GPT fixes factual errors/omissions and re-emits the same output contract), and writes Obsidian notes. No daemons in the pipeline itself — three launchd jobs (pull timer, inbox watcher, daily archive prune), plus an optional fourth (`com.plaud-obsidian.dash`, KeepAlive) that serves the read-only management dashboard. Docs, log messages, and comments are in Korean; keep that convention.

## Commands

```bash
python3 -m unittest discover -s tests                  # run all tests (stdlib only, no deps)
python3 -m unittest tests.test_process_inbox -v        # one test module
python3 -m unittest tests.test_process_inbox.SlugifyTest.test_truncates_to_60_chars  # one test
python3 scripts/_config.py                             # dump resolved config (sanity check; API keys masked as ***)
python3 scripts/_config.py --get INBOX_DIR             # resolve a single key (used by install.sh)
python3 scripts/claude_summarize.py transcript.txt     # standalone summary smoke test (needs ANTHROPIC_API_KEY)
python3 scripts/gpt_verify.py transcript.txt summary.txt  # standalone verification smoke test (needs OPENAI_API_KEY)
bash install.sh                                        # full install: brew deps, config.env, model (~1.5GB), launchd plists
bash uninstall.sh                                      # unload + remove launchd jobs (keeps notes/state)
python3 dashboard/serve.py                             # management dashboard → http://127.0.0.1:8791 (read-only)
tail -f logs/pipeline.log                              # main runtime log
launchctl list | grep plaud-obsidian                   # check jobs are loaded
```

There is no build/lint step. Python is stdlib-only by design — do not add third-party dependencies (the AssemblyAI client uses `urllib`, not `requests`, for this reason). The one exception is `scripts/whisperx_transcribe.py`, which runs under its own optional venv (`.venv-whisperx`, Python 3.11 + whisperx) — never under the system python3.

## Architecture

Three independent stages, each triggered by launchd (plists generated by `install.sh` pointing at this repo in-place; if script paths or PULL_INTERVAL change, `install.sh` must be re-run to regenerate them):

1. **`scripts/plaud_pull.py`** — timer (`StartInterval`, default 900s). Pages through `plaud files`, dedups against `state/pulled_ids.txt`, gets an S3 URL via `plaud audio <id>` (unexpected hosts are logged warn-only, download proceeds), downloads to `state/tmp/` (0700, `mkstemp`), then `shutil.move`s into `INBOX_DIR`. Recordings whose audio isn't server-side ready yet are retried via `state/pending_ids.txt` (96 attempts ≈ 24h) before being permanently skipped.
2. **`scripts/process_inbox.py`** — `WatchPaths` on `INBOX_DIR`. Transcription chain: `assemblyai_transcribe.py` (only if an API key is configured) → `whisperx_transcribe.py` via the `.venv-whisperx` interpreter (only if the venv exists) → ffmpeg + `whisper-cli` (always). Diarized tiers return utterances (`[{speaker, text}]`); whisper.cpp returns plain text wrapped as a single speakerless utterance. Then `claude_summarize.py` (Claude API via urllib, only if `ANTHROPIC_API_KEY` is configured) produces the summary *only* (the transcript is appended by code, so model output size doesn't scale with recording length); `gpt_verify.py` (OpenAI API, only if `OPENAI_API_KEY` is configured) cross-checks the summary against the transcript and re-emits a corrected version in the same `TITLE: ... ---SPEAKERS--- ---BODY---` contract (re-parsed by `parse_claude_output`; on success the note gets frontmatter `verified: true`). The note lands in `OUTPUT_DIR` as `{YYMMDD}_{title}.md` (YYMMDD = recording date parsed from the filename, `record_date()`), audio moved to `ARCHIVE_DIR`. Shared urllib helper: `scripts/_llm.py` (`retryable`/`post_json`/`call_with_retry` — retries only 429/5xx, never raises).
3. **`scripts/prune_audio.py`** — daily 03:00. Deletes archived audio older than `AUDIO_RETENTION_DAYS`; no-ops when the key is 0 (default) — deletion is strictly opt-in.

**`scripts/_config.py` is the single source of truth** for all paths/settings. Both Python scripts and `install.sh` (via `--get`) read it; never hardcode a path that `_config.py` already resolves. It parses repo-root `config.env` (gitignored, user-specific), expands `~`/`$HOME`/`$VAULT_PATH`, derives defaults, and defines all runtime paths under `state/` and `logs/`. `migrate_legacy_state()` moves v1 repo-root state files into `state/` — both scripts call it at startup; keep it idempotent.

### Reliability invariants (do not break these)

- **Atomic handoff**: pull downloads to `state/tmp/` (0700 dir, 0600 `mkstemp` files — never world-readable `/tmp`) first, then `shutil.move` into the inbox, so the watcher never sees a partial file. `process_inbox` additionally waits for file-size stability (`stable()`) because vault sync tools write incrementally, converts audio via temp files in the same `state/tmp/`, and writes notes atomically (hidden `.tmp` + `os.replace`).
- **Locks**: pull and process take a non-blocking `fcntl.flock` (`state/.pull.lock`, `state/.lock`) and exit quietly if already running.
- **Failure classification**: download failure → retry next run (id not recorded); audio not server-side ready → counted retry via `state/pending_ids.txt`, permanent skip (`state/skipped_ids.txt`) only after `MAX_PENDING_ATTEMPTS`; transcription failing `MAX_TRANSCRIBE_FAILURES` (3) consecutive times → audio quarantined to `INBOX/_failed/` and its fail count cleared (`state/transcribe_failures.txt`); note written but archive move failed → recorded in `state/processed_notes.txt` so the next run only retries the move, never re-transcribes/re-summarizes (no duplicate notes or API cost).
- **Graceful degradation, three times**: (a) each transcription tier falls back to the next — AssemblyAI failure/missing key/missing `urllib` response falls to WhisperX, missing venv falls to whisper.cpp, which is why `main()` still hard-requires ffmpeg+whisper-cli+model; (b) if `ANTHROPIC_API_KEY` is missing, the API call fails (all retries, or a fatal 4xx/`stop_reason: refusal`), or the output lacks the `TITLE: ... ---BODY---` contract (`parse_claude_output`), the note is still written with the raw transcript (`status: summary_pending`); (c) if `OPENAI_API_KEY` is missing, GPT fails, or its output doesn't re-parse, the Claude summary is kept unchanged (`verified: false`). Never lose a transcript. The guarded imports (`assemblyai_transcribe`, `claude_summarize`, `gpt_verify`) at the top of `process_inbox.py` must stay guarded.
- **launchd has a minimal PATH**: binaries (`plaud`, `ffmpeg`, `whisper-cli`, `claude`) are resolved to absolute paths with explicit candidate lists. New external tools must follow the same pattern.
- **Secrets stay out of git**: `config.env` (plus `config.env.*` backups, except the example), `.env`, `.assemblyai_key`, `.anthropic_key`, `.openai_key`, `.hf_token` are gitignored; each API key resolves env var → config.env → key file (launchd sees no shell env vars, so keys must live in config.env or key files). Never log key values. `_config.py` masks `*_KEY`/`*_TOKEN` in dumps **and refuses them via `--get`** (`is_secret_key`/`mask_secrets`); `load()` warns on stderr if a secret file is not mode 600, and `install.sh` re-chmods 600 on every run. Keep warnings on stderr — `--get` stdout is parsed by `install.sh`.

### Management dashboard (`dashboard/`)

Optional read-only web dashboard implementing `docs/PRD-dashboard.md` (design imported from the Claude Design project "대시보드 디자인 작업", Wanted Design System).

- **`dashboard/serve.py`** — stdlib-only HTTP server, **hardcoded to bind 127.0.0.1** (port 8791; 8787 is taken by another local service). Serves static files and generates `/dash-data.js` per request from live `state/`, `logs/`, `launchctl list`, note frontmatter, and `_config.py`. **Read-only invariant: it must never write pipeline state files.** Secrets are emitted only as set/unset booleans — never values. `parse_speakers()` handles both quoted and unquoted frontmatter arrays (real notes contain unquoted items with commas inside parentheses).
- **`dashboard/index.html`** — vanilla-JS port of the design (6 screens: 홈/처리 내역/실패·보류/노트 품질/로그/설정). Imports `./dash-data.js` as an ES module; polls with cache-busted dynamic import every 5s when served over http. `?demo=1` injects the incident-demo state, `?refresh=0` disables polling. Opened via `file://` it falls back to the committed `dashboard/dash-data.js` snapshot (demo data) — keep that file's export contract in sync with `serve.py`.
- **Action buttons are UI prototypes** — confirm dialogs work but no backend mutation exists yet; live-mode toasts say so. Wiring real actions (queue edits, `launchctl kickstart`) is the known next step and must respect the pipeline's flock/atomic-write invariants.
- **Persistence/remote**: `dashboard/com.plaud-obsidian.dash.plist` (copied to `~/Library/LaunchAgents/` by the user — auto-mode cannot write there) keeps the server running; `tailscale serve --bg --https=8443 http://127.0.0.1:8791` exposes it tailnet-only (never Funnel). Port 443 on this machine is already claimed by another tailscale serve mapping.

### Known fragility

`plaud files` has no JSON output; `parse_files_output()` regex-parses human-readable text (32-hex id + `YYYY-MM-DD`). A CLI format change breaks silently except for the zero-ids warning in `list_all_files()`. If the CLI ever gains JSON output, switch to it.

### Testing pattern

Logic meant to be tested is extracted into pure functions (`parse_files_output`, `load_pending`/`save_pending`, `load_processed`/`save_processed`, `parse_claude_output`, `parse_whisperx_lines`, `record_date`, `utterances_markdown`, `slugify`, `bump_fail`, `build_note`, `yaml_quote`, `unexpected_host`, `_parse_file`, `_expand`, `is_secret_key`/`mask_secrets`, `_llm.retryable`, and the `build_payload`/`extract_text` pairs in `claude_summarize`/`gpt_verify`) and covered in `tests/`. Tests `sys.path`-insert `scripts/` and import modules directly — module import runs `load()` and binary discovery, which must stay safe without `config.env` present. Follow this pattern when adding logic: extract pure function, test it, keep subprocess/IO at the edges.

## SKILL.md

`SKILL.md` is an agent-facing install/troubleshooting runbook (Claude Code skill format). When changing user-visible behavior (paths, fallbacks, troubleshooting cases), update README.md **and** SKILL.md together — they intentionally overlap.
