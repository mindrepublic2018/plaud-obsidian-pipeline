# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

macOS-only pipeline that pulls PLAUD recorder audio from PLAUD cloud (free tier, official `@plaud-ai/cli` only), transcribes locally with whisper.cpp, optionally summarizes via `claude -p`, and writes Obsidian notes. No daemons — two launchd jobs only. Docs, log messages, and comments are in Korean; keep that convention.

## Commands

```bash
python3 -m unittest discover -s tests                  # run all tests (stdlib only, no deps)
python3 -m unittest tests.test_process_inbox -v        # one test module
python3 -m unittest tests.test_process_inbox.SlugifyTest.test_truncates_to_60_chars  # one test
python3 scripts/_config.py                             # dump resolved config (sanity check)
python3 scripts/_config.py --get INBOX_DIR             # resolve a single key (used by install.sh)
bash install.sh                                        # full install: brew deps, config.env, model (~1.5GB), launchd plists
bash uninstall.sh                                      # unload + remove launchd jobs (keeps notes/state)
tail -f logs/pipeline.log                              # main runtime log
launchctl list | grep plaud-obsidian                   # check jobs are loaded
```

There is no build/lint step. Python is stdlib-only by design — do not add third-party dependencies.

## Architecture

Two independent stages, each triggered by launchd (plists generated by `install.sh` pointing at this repo in-place; if script paths or PULL_INTERVAL change, `install.sh` must be re-run to regenerate them):

1. **`scripts/plaud_pull.py`** — timer (`StartInterval`, default 900s). Pages through `plaud files`, dedups against `state/pulled_ids.txt`, gets an S3 URL via `plaud audio <id>`, downloads to `/tmp`, then `shutil.move`s into `INBOX_DIR`.
2. **`scripts/process_inbox.py`** — `WatchPaths` on `INBOX_DIR`. ffmpeg → 16k mono wav → `whisper-cli` → `claude -p` summary → note in `OUTPUT_DIR`, audio moved to `ARCHIVE_DIR`.

**`scripts/_config.py` is the single source of truth** for all paths/settings. Both Python scripts and `install.sh` (via `--get`) read it; never hardcode a path that `_config.py` already resolves. It parses repo-root `config.env` (gitignored, user-specific), expands `~`/`$HOME`/`$VAULT_PATH`, derives defaults, and defines all runtime paths under `state/` and `logs/`. `migrate_legacy_state()` moves v1 repo-root state files into `state/` — both scripts call it at startup; keep it idempotent.

### Reliability invariants (do not break these)

- **Atomic handoff**: pull downloads to `/tmp` first, then `shutil.move` into the inbox, so the watcher never sees a partial file. `process_inbox` additionally waits for file-size stability (`stable()`) because vault sync tools write incrementally.
- **Locks**: both stages take a non-blocking `fcntl.flock` (`state/.pull.lock`, `state/.lock`) and exit quietly if already running.
- **Failure classification**: download failure → retry next run (id not recorded); recording with no audio → permanent skip (`state/skipped_ids.txt`); transcription failing `MAX_TRANSCRIBE_FAILURES` (3) consecutive times → audio quarantined to `INBOX/_failed/` and its fail count cleared (`state/transcribe_failures.txt`).
- **Graceful degradation**: if `claude` is missing or its output lacks the `TITLE: ... ---BODY---` contract (`parse_summary`), the note is still written with the raw transcript. Never lose a transcript.
- **launchd has a minimal PATH**: binaries (`plaud`, `ffmpeg`, `whisper-cli`, `claude`) are resolved to absolute paths with explicit candidate lists. New external tools must follow the same pattern.

### Known fragility

`plaud files` has no JSON output; `parse_files_output()` regex-parses human-readable text (32-hex id + `YYYY-MM-DD`). A CLI format change breaks silently except for the zero-ids warning in `list_all_files()`. If the CLI ever gains JSON output, switch to it.

### Testing pattern

Logic meant to be tested is extracted into pure functions (`parse_files_output`, `parse_summary`, `slugify`, `bump_fail`, `_parse_file`, `_expand`) and covered in `tests/`. Tests `sys.path`-insert `scripts/` and import modules directly — module import runs `load()` and binary discovery, which must stay safe without `config.env` present. Follow this pattern when adding logic: extract pure function, test it, keep subprocess/IO at the edges.

## SKILL.md

`SKILL.md` is an agent-facing install/troubleshooting runbook (Claude Code skill format). When changing user-visible behavior (paths, fallbacks, troubleshooting cases), update README.md **and** SKILL.md together — they intentionally overlap.
