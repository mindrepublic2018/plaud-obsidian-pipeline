# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

macOS-only pipeline that pulls PLAUD recorder audio from PLAUD cloud (free tier, official `@plaud-ai/cli` only), transcribes it through a 3-tier engine chain (AssemblyAI cloud diarization → local WhisperX diarization → local whisper.cpp — the first two are opt-in, whisper.cpp is the always-available default), optionally summarizes via `claude -p` into a six-section meeting note with speaker-name inference, and writes Obsidian notes. No daemons — three launchd jobs only (pull timer, inbox watcher, daily archive prune). Docs, log messages, and comments are in Korean; keep that convention.

## Commands

```bash
python3 -m unittest discover -s tests                  # run all tests (stdlib only, no deps)
python3 -m unittest tests.test_process_inbox -v        # one test module
python3 -m unittest tests.test_process_inbox.SlugifyTest.test_truncates_to_60_chars  # one test
python3 scripts/_config.py                             # dump resolved config (sanity check)
python3 scripts/_config.py --get INBOX_DIR             # resolve a single key (used by install.sh)
bash install.sh                                        # full install: brew deps, config.env, model (~1.5GB), launchd plists
bash uninstall.sh                                      # unload + remove launchd jobs (keeps notes/state)
tail -f logs/pipeline.log                              # main runtime log
launchctl list | grep plaud-obsidian                   # check jobs are loaded
```

There is no build/lint step. Python is stdlib-only by design — do not add third-party dependencies (the AssemblyAI client uses `urllib`, not `requests`, for this reason). The one exception is `scripts/whisperx_transcribe.py`, which runs under its own optional venv (`.venv-whisperx`, Python 3.11 + whisperx) — never under the system python3.

## Architecture

Three independent stages, each triggered by launchd (plists generated by `install.sh` pointing at this repo in-place; if script paths or PULL_INTERVAL change, `install.sh` must be re-run to regenerate them):

1. **`scripts/plaud_pull.py`** — timer (`StartInterval`, default 900s). Pages through `plaud files`, dedups against `state/pulled_ids.txt`, gets an S3 URL via `plaud audio <id>`, downloads to `/tmp`, then `shutil.move`s into `INBOX_DIR`. Recordings whose audio isn't server-side ready yet are retried via `state/pending_ids.txt` (96 attempts ≈ 24h) before being permanently skipped.
2. **`scripts/process_inbox.py`** — `WatchPaths` on `INBOX_DIR`. Transcription chain: `assemblyai_transcribe.py` (only if an API key is configured) → `whisperx_transcribe.py` via the `.venv-whisperx` interpreter (only if the venv exists) → ffmpeg + `whisper-cli` (always). Diarized tiers return utterances (`[{speaker, text}]`); whisper.cpp returns plain text wrapped as a single speakerless utterance. Then `claude -p` produces the summary *only* (the transcript is appended by code, so claude output size doesn't scale with recording length), and the note lands in `OUTPUT_DIR` as `{YYMMDD}_{title}.md` (YYMMDD = recording date parsed from the filename, `record_date()`), audio moved to `ARCHIVE_DIR`.
3. **`scripts/prune_audio.py`** — daily 03:00. Deletes archived audio older than `AUDIO_RETENTION_DAYS`; no-ops when the key is 0 (default) — deletion is strictly opt-in.

**`scripts/_config.py` is the single source of truth** for all paths/settings. Both Python scripts and `install.sh` (via `--get`) read it; never hardcode a path that `_config.py` already resolves. It parses repo-root `config.env` (gitignored, user-specific), expands `~`/`$HOME`/`$VAULT_PATH`, derives defaults, and defines all runtime paths under `state/` and `logs/`. `migrate_legacy_state()` moves v1 repo-root state files into `state/` — both scripts call it at startup; keep it idempotent.

### Reliability invariants (do not break these)

- **Atomic handoff**: pull downloads to `/tmp` first, then `shutil.move` into the inbox, so the watcher never sees a partial file. `process_inbox` additionally waits for file-size stability (`stable()`) because vault sync tools write incrementally.
- **Locks**: pull and process take a non-blocking `fcntl.flock` (`state/.pull.lock`, `state/.lock`) and exit quietly if already running.
- **Failure classification**: download failure → retry next run (id not recorded); audio not server-side ready → counted retry via `state/pending_ids.txt`, permanent skip (`state/skipped_ids.txt`) only after `MAX_PENDING_ATTEMPTS`; transcription failing `MAX_TRANSCRIBE_FAILURES` (3) consecutive times → audio quarantined to `INBOX/_failed/` and its fail count cleared (`state/transcribe_failures.txt`).
- **Graceful degradation, twice**: (a) each transcription tier falls back to the next — AssemblyAI failure/missing key/missing `urllib` response falls to WhisperX, missing venv falls to whisper.cpp, which is why `main()` still hard-requires ffmpeg+whisper-cli+model; (b) if `claude` is missing or its output lacks the `TITLE: ... ---BODY---` contract (`parse_claude_output`), the note is still written with the raw transcript (`status: summary_pending`). Never lose a transcript. The guarded `import assemblyai_transcribe` at the top of `process_inbox.py` must stay guarded.
- **launchd has a minimal PATH**: binaries (`plaud`, `ffmpeg`, `whisper-cli`, `claude`) are resolved to absolute paths with explicit candidate lists. New external tools must follow the same pattern.
- **Secrets stay out of git**: `config.env`, `.assemblyai_key`, `.hf_token` are gitignored; the AssemblyAI key resolves env var → config.env → key file. Never log key values.

### Known fragility

`plaud files` has no JSON output; `parse_files_output()` regex-parses human-readable text (32-hex id + `YYYY-MM-DD`). A CLI format change breaks silently except for the zero-ids warning in `list_all_files()`. If the CLI ever gains JSON output, switch to it.

### Testing pattern

Logic meant to be tested is extracted into pure functions (`parse_files_output`, `load_pending`/`save_pending`, `parse_claude_output`, `parse_whisperx_lines`, `record_date`, `utterances_markdown`, `slugify`, `bump_fail`, `_parse_file`, `_expand`) and covered in `tests/`. Tests `sys.path`-insert `scripts/` and import modules directly — module import runs `load()` and binary discovery, which must stay safe without `config.env` present. Follow this pattern when adding logic: extract pure function, test it, keep subprocess/IO at the edges.

## SKILL.md

`SKILL.md` is an agent-facing install/troubleshooting runbook (Claude Code skill format). When changing user-visible behavior (paths, fallbacks, troubleshooting cases), update README.md **and** SKILL.md together — they intentionally overlap.
